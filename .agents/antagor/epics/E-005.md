## Problem

Users merge dozens of same-shaped CSV or Excel exports into one table, or split one table by a column or by size, with throwaway scripts each time.

## Goal

One address merges globs, folders and lists with _source and _sheet; a template in the target address splits by a column or by row count into files or sheets; {stem} converts many files one to one; the batch report and failure handling are the same in the library and the CLI.

## Acceptance (Given–When–Then)

- Given 'in/*.csv' with 3 files, When read, Then one table with a _source column naming each file; Given source_column=None, Then no _source
- Given 'in/**/*.xlsx', a folder, or a list of addresses, When read, Then all files are merged the same way
- Given 'reports/*.xlsx#*', When read, Then every sheet of every book is merged with _source and _sheet
- Given files with different columns, When read, Then a union with empty cells and a warning; Given strict=True, Then SCHEMA_MISMATCH (exit 2) lists the columns per file
- Given split_by='region' and target 'out/{region}.csv', When written, Then one file per region value; Given 'book.xlsx#{region}', Then one sheet per value; Given drop_split_column=True, Then the column is not in the files
- Given chunk_rows=10000 and 'out/part_{n}.csv' with 25 000 rows, When written, Then part_1..part_3 with 10 000, 10 000 and 5 000 rows
- Given a value with characters not allowed in file or sheet names, When split, Then they are replaced and the report lists the final names
- Given 'dataio convert in/*.csv out/{stem}.xlsx', When it runs, Then each CSV becomes its own xlsx
- Given a batch where one file fails, When it runs, Then it stops at the first error by default; Given keep_going=True, Then the rest are done and the report has errors [{uri, code, message}] with ok false
- Given --dry-run on a batch, When it runs, Then the report lists every target with exists, rows_before, rows_after and nothing is written
- Given a batch that replaces existing files, When it ends, Then each replaced file has its backup and restore works per file

## Implementation decisions

- Multi-source resolution in the address module: globs (with **), folders, lists; merge with _source/_sheet; union or strict schema check with SCHEMA_MISMATCH (exit 2)
- Target templates {column}, {n}, {stem} in the address module; split by split_by or chunk_rows; name sanitising for files and sheets
- Batch runner over the E-001 write pipeline: targets list in the report, stop on first error or keep_going with errors list
- New parameters source_column, strict, split_by, chunk_rows, drop_split_column, keep_going on the API and as CLI flags (parity test)

## Test seams

- Public library API: rb_dataio.read / write / convert / info / formats / backups / restore
- CLI under --json through CliRunner (envelope, exit codes, --dry-run/--confirm, parity), plus the template help, describe and auth snapshots
- Consumer contracts in tests/contracts (offline, keyless)

## Out of scope

- Parallel processing of files
- Merging by key (joins)
- Streaming of large batches

## Problem

A tool that writes through dataio puts out the column names its own steps made, all of them, in their order. A user or an agent that reads the JSON/JSONL cannot pick the columns, their order or their names at write time; each tool must add its own steps for it.

## Goal

write(), convert() and dataio convert take columns (keep these, in this order) and rename (old -> new); every target (csv, xlsx, json, jsonl, parquet, stdout, Google Sheets, records in memory) gets the chosen columns under the new names; a wrong name or a clash is refused with exit 2. Released as a non-breaking 0.1.x; the tag goes to the semkit Architect.

## Acceptance (Given–When–Then)

- Given a table with columns a,b,c, When write(df, 'out.csv', columns=['c','a']), Then out.csv has the header c,a and the rows hold the values of c and a.
- Given a table with columns a,b, When write(df, 'out.jsonl', rename={'b':'x'}), Then each record has the keys a and x in that order.
- Given columns and rename together, When write(df, t, columns=['b','a'], rename={'b':'x'}), Then the target columns are x,a: columns names the source columns and the selection comes before the rename.
- Given an unknown name in columns, When write or dataio convert runs, Then it is refused with INVALID_ARGUMENTS (exit 2), the message names the unknown name and lists the columns the table has, and no target is created or changed.
- Given rename of a column that is not in the table or is left out by columns, When write runs, Then it is refused with exit 2, naming that column and listing the columns there are; nothing is written.
- Given rename that makes two target columns share a name (two old names to one new name, or a new name equal to another kept column), When write runs, Then it is refused with exit 2 naming the clashing names; a swap rename={'a':'b','b':'a'} is accepted because the final names are unique.
- Given split_by='region' and columns without region, When write runs, Then the table splits by the source column region, the paths use its values, and region is not in the written targets; with region in columns it is written (and renamed) like any column.
- Given mode=append to an existing CSV, When the target columns (after columns and rename) differ from its header, Then the existing header check refuses it as before; when they match, the rows are appended.
- Given columns or rename, When the report is returned, Then its columns list the target column names, after selection and rename.
- Given format='records' and no target, When write(df, format='records', columns=..., rename=...), Then the returned data holds only the chosen columns under the new names.
- Given a Google Sheets target (the fake provider of the tests), When write with columns and rename, Then the sheet gets the chosen columns in order under the new names.
- Given dataio convert in.csv out.json --columns phrase,similarity --rename similarity=сходство, Then out.json records have the keys phrase and сходство; --columns and --rename may also repeat (--columns a --columns b, --rename a=x --rename b=y) and a rename value splits on the first '='.
- Given a malformed --rename value without '=', When dataio convert runs, Then it is refused with exit 2 and the message shows the expected form old=new.
- Given no columns and no rename, When any write runs, Then the output is the same as in 0.1.23 (no breaking change); dataio describe shows the two new options of convert.

## Implementation decisions

- WriteOptions gets columns (an ordered list of source names or None) and rename (a mapping or None); validated once, before any target work.
- One shaping step makes the target frame: select by columns, then rename; it runs inside the write path before the format adapters, stdout and records output, so every format gets the same frame. split_by works on the source frame before the shaping step; each part is then shaped.
- Wrong names and clashes raise InvalidArguments (exit 2) with the list of the table's columns; the check runs before any backup, temporary file or remote call.
- convert() and the CLI command convert pass the options through; the CLI parses --columns (comma list, repeatable) and --rename (old=new, comma list, repeatable, split on the first '=').
- Version 0.1.24; CONTEXT.md term: Колонки цели (target columns).

## Test seams

- The public Python API: rb_dataio write() and convert().
- The CLI command dataio convert (flags, exit code, message, describe).

## Out of scope

- Choosing or renaming columns on read (read, info).
- Computed columns, type casts or default values for missing columns.
- A separate dataio write CLI command.
- Column selection by pattern or by position.

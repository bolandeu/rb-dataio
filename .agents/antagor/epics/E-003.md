## Problem

Tools keep results in SQLite and DuckDB files and filter tables with SQL, each with its own connection code and no protection when a table is replaced.

## Goal

x.sqlite#table and x.duckdb#table read and write like files, with modes in one transaction and backups; query= runs SQL inside a base or over any source as the table 'data', directly over csv/parquet files for large ones.

## Acceptance (Given–When–Then)

- Given x.sqlite with table t, When read('x.sqlite#t') is called, Then t is returned; Given one table and no name, Then it is read; Given several and no name, Then SOURCE_NOT_FOUND lists them
- Given a .db file, When read, Then SQLite or DuckDB is chosen from the file signature
- Given query='select * from t where freq > 10' on a base, When read, Then the query runs inside the base
- Given query='select phrase from data where freq > 10' on a CSV, When read, Then only the matching rows and columns are returned
- Given a large CSV or Parquet file and query=, When read, Then DuckDB reads the file directly and pandas gets only the result
- Given write(df, 'x.duckdb#t') with mode replace, When t exists, Then t is replaced in one transaction and a backup of the old rows exists
- Given mode='append' with an extra column, When written, Then WRITE_FAILED names the extra columns and the table is unchanged; Given a missing column, Then it is NULL
- Given a write that fails midway, When it stops, Then the base is as it was before
- Given two processes appending to the same SQLite table, When both finish, Then all rows of both are there or one gets a clear WRITE_FAILED, never a broken base
- Given a SQL error in query=, When read, Then READ_FAILED shows the database message
- Given 'dataio info x.sqlite --json', When it runs, Then the tables are listed with their row counts

## Implementation decisions

- Base adapters for SQLite (stdlib sqlite3) and DuckDB in the core format registry; table from the address fragment or table=
- Type mapping to INTEGER, REAL, TEXT, TIMESTAMP; one transaction per write; no schema change on append
- query= layer: inside a base runs there; over any other source registers the frame as 'data' in DuckDB; over csv/parquet files DuckDB reads the file directly
- Backups of replaced tables as parquet in the E-001 backup store; restore puts the rows back

## Test seams

- Public library API: rb_dataio.read / write / convert / info / formats / backups / restore
- CLI under --json through CliRunner (envelope, exit codes, --dry-run/--confirm, parity), plus the template help, describe and auth snapshots
- Consumer contracts in tests/contracts (offline, keyless)

## Out of scope

- Postgres, MySQL, SQLAlchemy
- Primary keys, indexes, upsert
- Schema migration on append
- Streaming

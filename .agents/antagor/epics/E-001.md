## Problem

Every tool rewrites table reading and writing: leading zeros get lost, 'NA' becomes empty, Cyrillic breaks in Excel, data is overwritten with no way back. An agent meets a different interface and different errors in each tool.

## Goal

The library has read/write/convert/info/formats/backups/restore and the CLI has the same capabilities (convert, info, formats, backups, restore). Python objects, txt, csv, tsv, json, jsonl and stdin/stdout work; encoding and delimiter are detected and shown in the report; every error has a code and an action; every replace keeps a backup that restore brings back.

## Acceptance (Given–When–Then)

- Given a CSV in cp1251 with ';', When read(path) is called, Then a DataFrame with correct Cyrillic is returned; When convert or info runs on it, Then the report names encoding cp1251 and delimiter ';'
- Given encoding= or sep= passed, When the file is read, Then the given values are used instead of the detected ones
- Given a txt file, a list of strings or a multi-line string, When read, Then one column 'text' with one row per non-empty line is returned
- Given a list of dicts, {col: [values]}, {key: value}, a Series or a DataFrame, When read, Then columns follow the spec rules (keys as columns; key/value; Series name or 'value')
- Given a one-line string that is no existing address, When read, Then SOURCE_NOT_FOUND is raised naming the address, with the action to pass format='text'
- Given values 'NA', 'null', 'nan', 'None', '-', When read, Then they stay strings; Given an empty cell, Then it is missing and is written back as an empty cell
- Given a column with '007', '+7...' or a value of more than 15 digits, When read, Then the column stays text; Given as_text=True, Then every column is text; Given dtypes, Then the named column has that type
- Given a CSV with empty or duplicate header names, When read, Then names are repaired (col3, phrase_2) and the report has a warning; Given header=False, Then columns are col1..colN
- Given JSON records, an object of columns, or jsonl with nested objects, When read, Then nested objects become a.b columns and nested lists stay JSON strings
- Given data on stdin, When read('-') or 'dataio convert - out.csv' runs, Then the format is detected from the content
- Given write(df, 'out.csv'), Then UTF-8 with ',' is written and a report {target {uri, format, mode, rows, columns}, warnings} is returned; Given profile='excel', Then UTF-8-BOM with ';'
- Given write(df) with no target and format records|list|dict|text|csv|json, Then the object is returned and nothing is written
- Given JSON or jsonl target, When written, Then records with real Cyrillic and ISO dates are written
- Given target '-', When written, Then CSV goes to stdout (plain text for one column); Given --json too, Then stdout is one envelope with the rows in 'data'
- Given mode=error and an existing target, Then TARGET_EXISTS is raised and the file is unchanged; Given mode=append to a CSV with another header, Then WRITE_FAILED is raised and the file is unchanged
- Given a write that fails midway, Then the old file is intact (atomic write)
- Given two processes writing the same target at once, Then the target ends as one complete version, never a mix, and each run has its own backup
- Given an existing target replaced, When the write ends, Then a backup exists; 'dataio backups' lists it; 'dataio restore' brings the old content back and first backs up the current one
- Given restore without --confirm under --non-interactive, Then it is refused; Given --dry-run, Then it shows what would be restored and changes nothing
- Given convert where the target is the source, Then it is refused with TARGET_EXISTS unless overwrite=True or --confirm
- Given a replace that drops most rows or loses columns, Then the report has a warning naming the counts or the columns
- Given --dry-run on convert, Then the report shows exists, rows_before, rows_after per target and nothing is written
- Given backups over the limits (50 entries, 14 days, 2 GB) or an object over 500 MB, Then old backups are pruned, the big object is skipped with a warning; Given --no-backup, Then no backup is made
- Given an unknown extension, Then FORMAT_UNKNOWN is raised with the list of formats; Given a broken file, Then READ_FAILED names the address and the cause
- Given any error under --json, Then stdout has {ok:false, error {code, message, action}} and the exit code from the standard table
- Given 'dataio info SRC --json', Then format, rows, columns with types, a 5-row preview and the sheets or tables are returned; Given --limit N, Then at most N rows are read
- Given 'dataio formats --json', Then every format of this release is listed with read/write ability and its options
- Given any parameter of read/write/convert, Then the CLI has the flag with the same name (in_/out_ prefixes in convert), checked by a parity test
- Given 'dataio' with no arguments, Then help lists convert, info, formats, backups, restore and the template commands, and no 'run'

## Implementation decisions

- Public API at the package root: read, write, convert, info, formats, backups, restore; write returns a report for an address and an object without one (typed overloads)
- One parameter vocabulary shared by library and CLI (format, sheet, table, query, encoding, sep, header, as_text, dtypes, limit, mode, profile, overwrite, backup); flag = name with _ -> -; in_/out_ in convert for options of both sides
- Address module: parses one string into scheme, path, fragment (sheet or table), placeholders; explicit parameters override parsed parts. In this epic: local paths, '-', strings and objects
- Format registry: one adapter per format with read/write and its options; formats() and FORMAT_UNKNOWN lists come from it. This epic: objects, txt, csv, tsv, json, jsonl
- Detection: scheme, then extension, then content; CSV encoding chain utf-8-sig -> utf-8 -> cp1251; delimiter sniffed on 64 KB among , ; tab |
- Value normalisation: one step after every read (NA words, empty -> missing, leading-zero/15-digit rule, as_text, dtypes, empty rows removed, header repair)
- Write pipeline: resolve target -> dry-run -> safety checks -> backup -> atomic write -> report with warnings
- Report contract shared by library and CLI envelope: source {uri, format, encoding, delimiter, rows, columns}, target {uri, format, mode, rows, columns}, warnings, dry-run fields exists/rows_before/rows_after
- DataioError subclasses the template CliError; codes SOURCE_NOT_FOUND(2), FORMAT_UNKNOWN(2), FORMAT_UNSUPPORTED(2), TARGET_EXISTS(1), READ_FAILED(1), WRITE_FAILED(1); no new exit codes
- Backup store in the user data dir (platformdirs), declared in the template data-files list; entry = id, time, target, rows, old content; retention 50 / 14 days / 2 GB, skip > 500 MB
- CLI commands convert, info, formats, backups, restore; restore and convert-over-source use require_confirmation and --dry-run; template run placeholder removed; SKILL.md marks destructive commands
- Project config .rb_dataio/config.toml holds defaults only (e.g. csv.profile); no project is needed to run

## Test seams

- Public library API: rb_dataio.read / write / convert / info / formats / backups / restore
- CLI under --json through CliRunner (envelope, exit codes, --dry-run/--confirm, parity), plus the template help, describe and auth snapshots
- Consumer contracts in tests/contracts (offline, keyless)

## Out of scope

- Excel, parquet (epic excel-parquet)
- SQLite, DuckDB, query= (epic databases-query)
- Google Sheets, http(s) (epic google-http)
- Globs, folders, split_by, chunk_rows, {stem}, keep_going (epic bulk)
- Streaming reads and writes; S3; Postgres/MySQL
- Migrating semkit to dataio (semkit's own work)

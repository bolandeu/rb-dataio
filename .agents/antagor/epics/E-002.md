## Problem

Tables live in Excel books (xlsx, xls, xlsb, ods) and in Parquet files. Today every tool opens them its own way, overwrites a whole book to change one sheet, and pulls pyarrow for Parquet.

## Goal

read/write/convert/info handle Excel and Parquet like CSV: book.xlsx#Sheet, all sheets at once with _sheet, one sheet replaced while the others stay, a usable xlsx (autowidth, frozen header, autofilter), Parquet without pyarrow.

## Acceptance (Given–When–Then)

- Given book.xlsx with sheets A and B, When read('book.xlsx#B') is called, Then sheet B is returned; Given no sheet, Then the first sheet; Given a missing sheet, Then SOURCE_NOT_FOUND lists A and B
- Given .xls, .xlsb and .ods books, When read, Then each returns its first sheet with cell types kept and the leading-zero rule applied
- Given book.xlsx#*, When read, Then all sheets are stacked with a _sheet column; Given different columns, Then a union with a warning
- Given an existing book with sheets A and B, When write(df, 'book.xlsx#B') runs, Then B is replaced, A is unchanged, and a backup of the book exists
- Given a written xlsx, When it is opened, Then the columns are autowidth, the header row is frozen and has an autofilter; Given no sheet in the address, Then the sheet is Sheet1
- Given a book with charts or pivot tables, When a sheet is replaced, Then the report warns that they may be lost
- Given more than 1 048 576 rows, When written to xlsx, Then WRITE_FAILED is raised with the action to use csv or parquet and nothing is written
- Given a target .xls, .xlsb or .ods, When written, Then FORMAT_UNSUPPORTED is raised naming xlsx as the writable Excel format
- Given mode='append' to an xlsx sheet, When written, Then the rows go below the existing ones with the header checked
- Given a Parquet file, When read and written back, Then columns and types round-trip, and pyarrow is not installed
- Given 'dataio info book.xlsx --json', When it runs, Then the sheets are listed; Given 'dataio formats', Then xlsx, xls, xlsb, ods, parquet appear with their abilities

## Implementation decisions

- Excel read adapter on python-calamine for xlsx/xls/xlsb/ods; sheet from the address fragment or sheet=; '#*' stacks all sheets with _sheet
- xlsx write adapter on openpyxl: load the existing book, replace one sheet, keep the others; autowidth, frozen header, autofilter; row limit check before writing
- Parquet adapter through DuckDB (ADR 0003), no pyarrow dependency
- Both plug into the core format registry and the write pipeline (backup, atomic write, modes) of E-001 without changing the API or flags

## Test seams

- Public library API: rb_dataio.read / write / convert / info / formats / backups / restore
- CLI under --json through CliRunner (envelope, exit codes, --dry-run/--confirm, parity), plus the template help, describe and auth snapshots
- Consumer contracts in tests/contracts (offline, keyless)

## Out of scope

- Excel styling beyond autowidth, frozen header and autofilter
- Writing xls, xlsb, ods
- Formulas: values only
- Streaming of large books

## Problem

Reports live in Google Sheets and remote CSVs. Each tool sets up the service account itself, fails with unclear 403s, turns 007 into 7, and can wipe a shared sheet with no way back.

## Goal

A Google Sheets URL or gsheet://id#Sheet reads and writes like a file; the key is found by the standard order and checked by auth status; a 403 says whom to share with; replacing a non-empty sheet asks first and keeps a backup; http(s) CSV and JSON links read directly.

## Acceptance (Given–When–Then)

- Given a Google Sheets browser URL with gid, When read, Then that sheet is returned; Given gsheet://<id>#Sheet1, Then Sheet1
- Given the key in --credentials, DATAIO_GOOGLE_*, the keychain or GOOGLE_APPLICATION_CREDENTIALS, When dataio runs, Then the first found in that order is used; Given none, Then AUTH_REQUIRED with the action to log in
- Given 'dataio auth status --check --json', When it runs, Then the google entry has source, status and the service account email, in the standard report shape
- Given a sheet not shared with the service account, When read or written, Then AUTH_REQUIRED says 'Share the sheet with <email> as Editor'
- Given a missing sheet name, When written, Then the sheet is created; Given start='A5', Then the data starts at A5
- Given values '007' and '=1+1', When written, Then the sheet shows 007 and the text =1+1 (RAW); Given value_input='user', Then Google parses them
- Given a non-empty sheet and mode replace, When the CLI runs without --confirm under --non-interactive, Then it is refused; Given --dry-run, Then it shows rows_before and rows_after and changes nothing; Given the library without overwrite=True, Then TARGET_EXISTS
- Given a confirmed replace, When it ends, Then the old values are in a backup and restore puts them back; the sheet formatting is kept
- Given 25 000 rows, When written, Then they go in batches of 10 000; Given 429 or 5xx, Then the batch is retried with backoff; Given more than 10 million cells, Then an error before writing
- Given an http(s) CSV or JSON URL, including a 'Publish to web' link, When read, Then the table is returned; Given 404 or a timeout, Then PROVIDER_ERROR with the status
- Given any Google or http test, When the suite runs, Then no network is used (injected client)

## Implementation decisions

- Provider google in the template credentials layer: service-account field bag, resolution flag -> DATAIO_GOOGLE_* -> keychain -> GOOGLE_APPLICATION_CREDENTIALS (legacy env); health_check is one cheap authorised call; gspread errors mapped to AuthRequired / ProviderError (ADR-level: no secrets in config)
- Google Sheets adapter in the format registry: address by URL with gid or gsheet://id#sheet; modes replace/append/error; create sheet; start cell; RAW writes; batches of 10 000; backoff on 429/5xx; 10M-cell check
- Confirmation for replacing a non-empty sheet through the template require_confirmation; overwrite=True in the library; backups of old values as parquet in the E-001 store
- http(s) adapter on the template HttpProvider (retries, timeouts, error mapping); the content format from the URL or the response

## Test seams

- Public library API: rb_dataio.read / write / convert / info / formats / backups / restore
- CLI under --json through CliRunner (envelope, exit codes, --dry-run/--confirm, parity), plus the template help, describe and auth snapshots
- Consumer contracts in tests/contracts (offline, keyless)

## Out of scope

- Creating new Google Spreadsheets
- Formatting of written sheets
- S3 and other object stores
- OAuth user login (service account only)
